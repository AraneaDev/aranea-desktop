# Unified clock dropdown

Approved by Tim on 2026-10-20 after the proposal for Calendar, World Clock and Weather tabs. First publish and install the already merged sudo/shutdown fixes (2.34.0); build this feature afterwards.

## Behavior

Clicking the bar time opens a single Aranea dropdown anchored to that actual clock button. A top bar offers Calendar, World Clock and Weather tabs, styled like existing System/Network tabs. Normal clock open starts on Calendar. The three pages preserve their complete existing functionality, including calendar navigation and life fields, the mapped globe and sun/daylight, editable cities/home/order, and the weather location editor/forecast. Only the selected page is active. Calendar location lookup and sun timer require the Calendar page; cheap global time-label clocks and local file watches may stay active. Its inherited PanelController.open drives the existing opened guards. Embedded Weather startup and refresh timers stay dormant while its page is inactive; standalone weather background behavior remains unchanged. The separate weather and world-clock bar icons are consolidated into the clock.

One native keyboard panel owns focus, placement, the open indicator, outside-click dismissal, Escape, and bar popout handoff. On a top bar it opens below the clock, with existing screen fitting and orientation-aware placement retained elsewhere. No additional hidden standalone windows are created by embedded controllers. Existing page-specific keys work on the active page; editing keys remain with their editor. Changing pages cancels unsubmitted edits and clears stale pointer/cursor state; saved values remain intact. Ordinary time label formatting and right/middle click behavior stay intact.

## Composition and interfaces

Clock Panel.qml owns the single KeyboardPanelFrame, with centerOnBar:false and anchorItem pointing at the real time button. It exposes activePage (calendar/worldclock/weather), selectPage(page), openSection(page), toggleSection(page), persistSection(page, values), and activePageController. Clock BarWidget forwards openSection/toggleSection/isSectionOpen, exposes weatherPanel/worldClockPanel aliases for scoped peer discovery and keeps clockPanel. The owner remains the mounted clock bar widget.

Weather and World Clock Panels use the existing Bluetooth embedding pattern: embedded:false, embeddingHost:null, hostedDropdown:null, hostedFocusTarget:null, and readonly activeDropdown selecting the embedded view or standalone view. Their standalone frames/views are created only when !embedded. Pass embedded:true, embeddingHost, nested settings and test boundaries as initial Loader.setSource properties, before construction; never load standalone then flip the flag in onLoaded. Embedded World Clock activation must not copy hostWidget.settings wholesale over its nested settings binding. Lifecycle adapters activate/deactivate the controller without asking the shared popout coordinator to claim a second window. activateEmbedded() performs the same refresh/probe/settings work as existing open, and deactivateEmbedded() cancels pending edit/fetch/focus appropriately without closing the owner. Public open/close/toggle select the owning section or close the owner when embedded. Deferred focus checks that the controller is still the selected open page.

Existing ClockDropdown, WeatherDropdown and WorldClockDropdown presentation components and action handlers remain authoritative. The clock supplies hosted view/focus references and forwards page keyboard actions through explicit navigateKeyboard/activateKeyboard/textKeyboard/deleteKeyboard/disarmPointer adapters where existing controllers need them. A missing optional controller leaves Calendar usable and hides its unavailable tab.

## Settings and migration

Calendar settings stay on the clock entry. Weather settings live under clock.weather, World Clock settings under clock.worldClock. World Clock city writes delegate to persistSection('worldclock', values); that writer merges into the latest full clock entry, preserving unrelated keys and other pages, then writes through the existing own-entry shell facade. Weather location remains in its existing weather.json file. Weather peers are found through the clock's own entry ID and its weatherPanel alias; never broaden moduleWidgets access.

A dedicated scripts/lib/clock-shell-config.jq performs a reversible, idempotent projection after stock-to-Aranea retargeting. Only consolidate when the owning clock and corresponding deployed plugin exist. Preserve every removed entry's original section/index/shape/settings under clock.araneaClockMigration. Preserve an already present nested value over a stale original projection. Remove only the corresponding standalone entries. On theme release, merge current nested preferences into restored original entries at their saved locations, preserving original string shape if unchanged and preserving later user additions. Restore edited nested city/weather preferences, not stale original copies. Restore before Aranea-to-stock retargeting. Symlinked shell.json behavior remains intact. Repeated repair/release/return must not duplicate icons or lose cities. Standalone entries continue to work when Clock is absent.

## Compatibility routing

The trusted bar host retains exact standalone widget precedence. If the requested weather or Elsewhen widget is absent, summon/hide/isOpen route narrowly to the matching section of the focused screen's clock. Treat another open clock page as closed for a different section's toggle, so toggling Weather while Calendar is open selects Weather. Clock BarWidget owns embedded compatibility IPC (optionally factored into ClockCompatIpc.qml). Weather Panel creates its existing native IPC only in standalone mode; World Clock standalone BarWidget keeps its existing IPC. Clock compatibility handlers are disabled for each matching standalone ID present in the existing public bar.layoutConfig. Preserve native Weather open/close/show/hide/toggle/edit and Elsewhen open/close/show/hide/toggle/showcase. Weather edit selects its page before guarded editor focus; showcase finds an open clock peer and its worldClockPanel. Direct IPC retains the existing per-monitor registration behavior; trusted shell aliases select the focused monitor. No duplicate standalone/embedded IPC ownership. Do not expand plugin moduleWidgets or service permissions. Direct clock open selects Calendar; refresh retains the current section.
