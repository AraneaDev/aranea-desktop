# Omarchy 4.5.0 port triage

This records the scope recovered from issue [#226](https://github.com/AraneaDev/aranea-desktop/issues/226)
and the request for a full port plan plus the drift-tool fix. It is a port
proposal, not a claim that the desktop has been upgraded or tested on 4.5.0.

## Baseline and boundaries

- Aranea baseline: `4ab9436` (2.39.4); drift-tool fix: PR #230.
- Upstream base: `v4.5.0-rc1`, `03ff1eff3812933f7088484533784d2f63eaf19a`.
- Upstream target: `v4.5.0`, `97e664bd971fa5a8691d89440d3738143499c438`.
- Keep Qt 6.12 and the reviewed Quickshell build used by CI.
- Keep Aranea's notification inbox, quiet hours, shared popup system, unified
  clock, tray management, provider restrictions, and agent activity ownership.
- Port behavior into Aranea's existing components; do not overwrite forks.
- Change `.omarchy-version` only after all required ports and acceptance pass.
- No live desktop installation, lock, monitor, notification, or network changes
  are part of preparing this plan. Runtime acceptance uses the test sandbox.

The drift report identifies 13 changed forks out of 18, all four platform
paths changed, four unchanged forks, and one missing upstream path. That count
is a review inventory, not the number of patches needed.

## Host platform changes

`shell/Commons`, `shell/Ui`, `shell/services`, and `shell/shell.qml` are supplied
by the installed Omarchy host. A host on 4.5.0 receives those fixes; this
repository does not vendor those paths. The current CI pin still loads rc1,
so passing existing CI alone does not establish compatibility with 4.5.0.

The final gate must run against an actual 4.5.0 shell checkout. Check popup
growth and closing input, widget metrics/press feedback, dropdown toggling,
slider reach, translation loading, plugin enable restoration, ignored Python
bytecode writes, and unreadable `shell.json` protection through the existing
host integration. Do not manufacture duplicate platform implementations here.

## Notification contract

The 4.5.0 sender encodes action buttons in the `omarchy-actions` hint as a JSON
array of `{label, argv}` objects. Validate bounded labels and argv before
storing or running them. Never evaluate the notification's data as a shell
command. Keep the existing `omarchy-exec-argv` click behavior.

For the newest live card, `act()` returns `none` when no card exists. With no
meaningful click or buttons it dismisses the card; with exactly one available
choice it invokes that choice; with more than one it enters keyboard mode.
A real default click counts as a choice. Guessing an app from its display name
does not make a card meaningfully clickable. `keyboard()` toggles keyboard
ownership and returns `on`, `off`, or `none`. Escape, dismissal, expiry, and
service teardown must release ownership and resume paused expiry timers.
Numbered choices must match visible order, including a meaningful card click.
No keyboard action may fall through to another notification after its original
card disappears. Restored inbox entries must not revive libnotify action
objects whose sender no longer exists.

Retain Aranea's inbox semantics for its existing IPC methods. Audit the actual
4.5.0 bin scripts and bindings against the implemented methods, including
whether `invokeAction` has a caller, before declaring compatibility complete.

## Delivery and acceptance

Split implementation into independently reviewable PRs: menu compatibility;
notification actions; notification keyboard IPC; sender/replacement semantics; clock and lock reliability;
network/display/weather behavior; bar/tray/picker rendering; then host pin and
full acceptance. The plan defines exact files, test examples, upstream references,
and gates for those units. A port can be rejected without discarding the rest.

Issue #226 stays open until the required behavior is shipped and the target
pin passes acceptance. A plan or a zero-drift report alone is not a resolution.
