# Aranea menu

`araneadev.menu` is the command menu and its bar launcher. The manifest exposes
`Menu.qml` as `menu` and `BarWidget.qml` as `bar-widget`.

## Responsibilities

- Load and merge the shipped menu model with user overrides.
- Resolve routes, aliases, parent paths, and visible descendants.
- Batch guard checks so rows share command and package readers.
- Search applications and menu rows while preserving favorites and recents.
- Compose the menu window, card chrome, root tiles, result list, and app
  library.

`Menu.qml` is the composition root and the menu's core: it owns items,
display, selection, navigation, routes, and keys, and wires up the
child components below. `MenuWindow.qml` owns the window contract.
`MenuModel.js` remains a stable QML-compatible facade while focused
modules own history, search, and tree traversal.

## Components

- `MenuStyle.qml` owns colors, fonts, metrics, branding paths, the root
  tiles, and the root context band (workspace and clock).
- `MenuSources.qml` loads and watches the JSONC menu sources (Omarchy's
  default menu file and the user's extension) and merges them.
- `MenuAppHistory.qml` persists favourites and recent app ids to
  `menu.json` in the Aranea state directory, builds the generated Apps
  rows, and drives the uninstall prompt.
- `MenuProviders.qml` runs the bash providers that fill submenus such as
  Fonts and Power Profile on demand, one process at a time.
- `MenuGuards.qml` batches `when:` (visibility) and `checked:` (check
  mark) bash guard evaluation into one process per (re)load.
- `MenuDmenu.qml` serves dmenu-style select/input requests: it holds the
  request, turns options into rows, and writes the answer.
- `MenuLayout.js` is the pure layout math for the menu card: running
  row-list heights, the space the card can give its rows, the fold that
  ends mid-row when the rows do not fit, the scroll position that keeps the
  cursor row visible with a peek of its neighbor (`revealContentY`), and
  the screen dimension to lay the card out against before the layer
  surface reports its own size (`screenExtent`).

## Logic boundaries

- `MenuModel.js` is a stable QML-compatible facade generated by
  `tools/js-facade-generator.mjs` from its sibling modules:
  `MenuPresentation.js` (display labels and row projections),
  `MenuSearch.js` (matching and ranking), `MenuTree.js` (routes,
  ancestry, visibility, and breadcrumbs), `MenuAppRows.js` (merging app
  rows into the item tree), `MenuItemParsing.js` (parsing JSONC entries
  and swapping provider rows), and `MenuGuardScript.js` (building the
  batched guard script).
- QML owns focus, navigation, and user interaction.
- The highlight is the keyboard cursor only: hover never moves it. The
  first row is highlighted on open and after each keystroke, so Enter
  launches the top match. Root tiles tint on hover only after a real
  pointer move (PointerMoveGate). Row and tile clicks are keyed by item
  or tile id and settled (`ClickSettle`): a release on a row that holds
  another item is refused, and so is a click within 300 ms of the rows
  changing, scrolling or appearing under a still pointer.

Shared keyboard and panel behavior comes from `araneadev.shared`.

## Validation

Run `tests/qml-behaviour.test.sh menu menu-root menu-style menu-sources
menu-guards menu-app-history menu-providers menu-dmenu menu-components
menu-window-components menu-pointer` and the menu JS suites.
